2) Routes & API (Astro)

Public
	•	src/pages/forms/[slug].astro
	•	Server load: fetch active form + fields, render the dynamic form.
	•	On submit, POST to /api/forms/submit with { formSlug, data }.
	•	Show success/failure toast. Keep styling consistent with current inputs/buttons.

API
	•	src/pages/api/forms/submit.ts
	•	Accept POST JSON: { formSlug: string, data: Record<string, any> }.
	•	Validate required fields based on form_fields.required.
	•	If form is inactive or slug not found → 404.
	•	Insert into form_submissions (jsonb).
	•	Basic anti-spam: throttle per IP (simple 1 submission/10s in-memory or skip if not needed).
	•	Respond { ok: true } or { ok: false, error }.
	•	src/pages/api/admin/forms.ts
	•	Use service role key.
	•	Methods:
	•	POST /api/admin/forms → create form { name, slug, description, is_active }
	•	PUT /api/admin/forms → update form by id
	•	DELETE /api/admin/forms?id=... → delete form by id
	•	Return normalized JSON with errors.
	•	src/pages/api/admin/form-fields.ts
	•	Use service role key.
	•	Methods:
	•	POST → create field { form_id, label, field_name, field_type, required, options[], order_index }
	•	PUT → update field by id
	•	DELETE ?id= → delete field by id
	•	src/pages/api/admin/submissions.ts (optional listing)
	•	GET ?form_id= → list submissions (for admin table/export CSV).

Keep error logging (console.error) for quick debugging.

4) Dynamic Form Rendering Rules (Public)
	•	Render by field_type:
	•	short_answer → <input type="text">
	•	paragraph → <textarea>
	•	radio → group of radios from options[]
	•	checkbox → group of checkboxes from options[] (send array)
	•	select → <select> options from options[]
	•	rating → 1–5 clickable inputs or a select (keep minimal)
	•	date → <input type="date">
	•	time → <input type="time">
	•	Use field_name as the submission key.
	•	Respect required attributes in the DOM and also validate on server.
	•	On submit, collect values into { [field_name]: value | string[] } and POST to /api/forms/submit.
